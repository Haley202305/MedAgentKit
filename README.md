# paper-insight-reporter

把一篇研究论文逐节拆开，产出一份**可溯源、带图锚点**的阅读报告——不是摘要，不是翻译，也不是读后感。

> Turn a research paper into a traceable, figure-anchored reading report — not a summary.

适用于单细胞、空间转录组与其他组学类论文；方法学论文与综述类不适用（见下方"适配"一节）。

---

## 它解决什么问题

读论文时最容易出问题的地方不是"看不懂"，而是三类失真：

- **数值漂移**：把 `nearly half` 记成"超过一半"，把样本数写成细胞数
- **证据串层**：把作者的推断当成实测结论，把预测的配体-受体互作当成功能证据
- **结构丢失**：读完记住了几个漂亮结论，却说不清它们各自站在哪张图的哪个面板上

这个 skill 用固定流程与固定模板把这三类失真堵住：**每条发现都要能指回原文位置，每个数值都照抄原文口径，每处推断都单独标注。**

## 四条铁律

1. **数值保真**——样本数、个体数、比例、P 值一律照抄原文口径，不做同义改写。原文没报告的写 `未报告`，不推测、不补齐。
2. **原文锚点**——每条发现都要能指回章节 + 图/表编号 + 关键英文短语。
3. **证据分层**——分清"作者直接测量的""从图表反推的""作者的推断"三类，不揉成一句话。
4. **术语随文建档**——缩写首次出现处即记录全称；原文没展开的标注"原文未定义"并指明去哪核对。

## 工作流

| 阶段 | 做什么 | 产出 |
|---|---|---|
| 0 | 建立骨架 + 引言四段式提取 | 小节清单（`result-01` … `result-NN`）、引言四段 |
| 1 | Results 逐节拆解，一个小节一份单元 | 每节：一句话结论 / 主要发现 / 方法与复现要素 / 逻辑张力与问题 |
| 2 | 回 Methods 反向核对参数 | 参数回填 + 正文与 Methods 的不一致清单 |
| 3 | 讨论提取 + 问题核对 | 核心论断 / 自述局限 / 模型与转化；问题集中成末节 |
| 4 | 合并渲染 | 单文件 HTML 报告 |

## 报告骨架

默认五段，顺序即原文逻辑：

```
数据  →  引言  →  结果（按作者小节逐节）  →  讨论  →  问题与方法核对
```

三条成文规则：问题一律集中到末段；重复出现过的方法第二次之后只写"同 result-XX"；**只谈这一篇文献**，不做跨文献比较。

### 适配

五段是默认值，不是固定模板：

| 情形 | 处理 |
|---|---|
| 结果小节的划分 | **永远跟随作者自己的小节标题** |
| 没有独立的"数据"部分 | 并入引言或第一节 |
| 没有讨论部分 | 直接以"问题核对"收尾 |
| 方法学论文 | 换成 问题 → 方法 → 验证 → 讨论 → 问题核对 |
| 遇到没见过的分析类型 | 临时提取 → 固化成新模块 |
| 纯综述、评论、社论 | 不适用 |

## 模块

模块按**结果主题**切分，是一组可复用的信息类型，不是封闭集合。

| 模块 | 覆盖的信息类型 |
|---|---|
| M1 | 数据来源与队列构成 |
| M2 | 分群与细胞组成 |
| M3 | 分型定义与组间特征 |
| M4 | 独立维度刻画与分组互证 |
| M5 | 轨迹与拟时序 |
| M6 | 临床关联与预后分析 |
| M7 | 细胞通讯与配体-受体推断 |
| M8 | 空间与实验验证 |

每个模块文件包含触发信号、必填字段、交付格式与**一个**完整实例，用于校准输出格式。

**所有实例均为虚构示例**（文件内标注"不对应任何真实文献"），不使用任何真实论文的内容。这样模块文件可以直接随 skill 分发，不涉及第三方论文版权，读者也不会把示例中的数字误当成真实发现。需要真实案例时，看对应论文自己的拆解产出。

## 安装

克隆到 Codex 的 skills 目录：

```bash
git clone https://github.com/<your-account>/paper-insight-reporter.git \
  "${CODEX_HOME:-$HOME/.codex}/skills/paper-insight-reporter"
```

安装后即可用 `$paper-insight-reporter` 显式调用，或在"读这篇文献、出个报告"这类请求下自动触发。

## 使用

```
$paper-insight-reporter 读这篇文献，生成报告   （附上 PDF）
```

典型过程：先搭骨架并给出小节清单，然后**逐节交付**——每节交完先给你看，你可以在这一步纠正口径，再继续下一节。全部读完后再做 Methods 核对与讨论提取，最后合并成一份 HTML 报告。

## 产出

```
work/<paper-slug>/                       中间产物，不作为交付物
├── 00-index.md                          索引：小节清单、图表清单、术语表、问题清单
├── result-01-<slug>.md …
├── 02-introduction.md
├── 03-methods-cross-check.md
├── 04-discussion.md
└── 05-issues-and-checks.md

outputs/<paper-slug>/
└── <slug>-report.html                   交付物：单文件、无外部依赖
```

HTML 报告**不含任何 CDN 依赖**：断网可打开，浏览器里直接 Ctrl+P 可导出排版整齐的 PDF。

## 设计取舍

几处刻意的选择，都是被实际使用中的问题逼出来的：

**只交付 HTML，中间 markdown 留在 `work/`。** 手写 HTML 意味着把几万字中文重抄一遍，必然引入偏差；用脚本从 markdown 渲染，内容只写一次，改内容时改 md 重跑即可。

**问题集中到末节，不回填到各节。** 早期版本把问题散落在每节末尾，结果是同一处缺陷在多节重复出现，读者要自己拼。集中之后，"某节的结论为何不可靠"一眼能连起来看。

**每个模块只保留一个实例。** 模块文件是格式校准用的，不是论文案例集。多篇论文的实例堆在一起会让文件无限膨胀，而论文的实际产出应当独立存放。

**不写跨文献比较。** 报告只谈这一篇。评价性判断用文献自身的内部标准（"参数可完整回填""阈值未做敏感性分析"），不用相对排名——否则换一篇文献就要改动既有措辞。

**图型能力对照独立成文。** [references/figure-map.md](references/figure-map.md) 维护一张"图型 → 能支持什么 / 不能支持什么"的对照表。它的作用是防止把图能说的话说过头，例如桑基图的分量是样本而非细胞、KM 曲线交叉时 log-rank 不可解释、UMAP 不承载比例信息。

## 已知限制

- **双栏排版提取困难**：Nature 系列等双栏 PDF 用常规方式提取会把阅读顺序打乱，需要按栏重排（仓库不含处理脚本，属于外部步骤）。
- **面板级完整性无法从文本层保证**：图注在提取时常被切碎，报告能保证小节级的图覆盖，面板级内容建议对着 PDF 复核。
- **依赖 Methods**：若论文把方法细节整体放在补充材料而正文只有一句话，参数核对只能记为缺口，无法回填。
